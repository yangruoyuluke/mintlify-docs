# Mintlify 文档仓库结构说明（v7）

更新时间：2026-05-25

## 1. 本次反馈

用户明确指出，问题不是单个知识库页面，而是整套中文文档都需要按“自然引导用户操作”的方式书写。现有部分页面虽然结构清楚，但仍偏字段说明、按钮说明或文档化表达，缺少真实操作场景中的判断标准。

## 2. 调整目标

- 将中文文档整体口吻统一为对真实用户的引导，而不是模块说明书。
- 减少只描述“点击哪里、页面有什么”的空步骤。
- 在步骤中补充业务判断：什么时候该用、怎么确认、怎么排查、怎么优化 AI 效果。
- 保留 API 参数、指标定义等必要表格，但在表格前后补充使用场景和阅读方法。
- 继续遵循 `DESIGN.md` 的包豪斯、Apple、OpenAI 风格：克制、清晰、可执行。

## 3. 本次修正范围

重点更新中文生产导航和旧路径中的页面：

| 范围 | 调整 |
| :--- | :--- |
| 快速开始 | 改写关于 MarsMind、准备工作、上线流程，强调先选试运行场景、准备真实资料和逐步扩大范围 |
| AI 协作指南 | 改写基础协作、进阶协作、对话方式，减少说明书口吻，强调身份、指令和反馈的真实协作方式 |
| 管理后台 | 改写登录、数据看板、助手设置、技能库、知识库、网页聊天、操作指南、账号设置等页面 |
| 旧路径页面 | 同步旧的 flat 路径页面，避免旧链接进入时出现另一套文风 |
| 开发文档 | 为 API 和技能模块页补充“什么时候需要看、如何判断使用场景”的引导 |
| 设计规范 | 增加全站中文文案默认使用“你”、参考型表格需要配套使用场景说明的规则 |

## 4. 后续建议

后续新增页面时，不要先写“功能概览 + 操作路径 + 字段表”。应该先回答用户真实会关心的三个问题：我什么时候需要来这里、我应该如何判断、做完以后怎么确认效果。
